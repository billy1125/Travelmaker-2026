依目前行程，盤點各段住宿，為尚無指南的旅宿建立 `hotel/` 檔案，補充既有檔案缺漏的資訊，產出可直接寄給館方的英日文聯絡信件，並把館方的回信整理進指南。

## 旅宿的定義

行程中**實際過夜**的地點，包含旅館、商務飯店、旅館式公寓、民宿、青年旅館。

- 日歸行程中途休息的設施不建檔
- 同一間旅宿分兩段入住（中間離開再回來）仍只開一個檔案
- 尚未訂房、只是候選名單的旅宿不建檔；使用者明確要求比較時，另以對話回覆，不寫進 `hotel/`

## 執行步驟

### 1. 讀取格式規範

先讀 `../update-itinerary/reference/hotel_format.md`（相對於此 SKILL.md 所在目錄），確認命名規則、範本結構與「訂房文件優先」等原則。**後續產出一律依該規範。**

### 2. 盤點旅宿

- 讀 `itinerary.md` 的住宿分段與「行程原則」中與住宿有關的限制
- 讀 `days/` 內全部 `yyyyMMDD.md`，抓出標頭的 `- **住宿：**` 列，以及時間表中的入住、退房、早餐、出發時間
- 用 Glob 列出 `assets/` 內的訂房文件（PDF），取得訂房事實
- 整理成清單：**旅宿名稱｜期間｜晚數｜訂房文件｜目前資料散落在哪些檔案**

**讀取訂房 PDF 的方式**：本環境沒有 `pdftoppm`，Read 工具無法直接讀 PDF。改用 conda 環境的 PyMuPDF 抽文字到暫存檔再讀：

1. 寫一支小腳本到暫存目錄，用 `fitz`（PyMuPDF）開檔，把各頁 `get_text()` 串起來寫入 `.txt`
2. 以 `conda run -n claudecode python {腳本} {pdf} {txt}` 執行（`conda run` **不支援含換行的 `-c` 參數**，一定要寫成檔案；也不要讓腳本 print 中日文，`conda run` 的 stdout 是 cp950 會爆）
3. 用 Read 讀那個 `.txt`

### 3. 比對既有指南

- 用 Glob 列出 `hotel/*.md` 並讀取
- 將旅宿分成三類：
  - **已有完整指南**——略過
  - **已有但缺漏**（例如缺周邊機能、缺信件、缺大浴場時間、館方回信尚未收錄）——補充既有檔案
  - **尚無指南**——新建

### 4. 提出清單並取得使用者同意（必要，不可略過）

**在建立任何檔案之前**，先把步驟 2、3 的結果整理成清單交給使用者確認：

| 旅宿 | 期間 | 晚數 | 訂房文件 | 目前狀態 | 建議動作 |
|------|------|------|----------|----------|----------|
| {旅宿名稱} | {MM/DD–MM/DD} | {N} | {有／無} | 尚無指南／已有但缺 {項目} | 新建 `{檔名}.md`／補充 `{檔名}.md`／略過 |

同時說明：

- 每間旅宿**為什麼需要建檔**，以及打算查證哪些項目
- 判斷為「略過」的旅宿及理由，讓使用者有機會加回來
- **若訂房文件含確認碼、PIN、門鎖密碼，先問使用者要不要寫入檔案**（預設寫入，因為現場查閱方便；使用者要求遮蔽時改寫成「見 `assets/{檔名}.pdf`」）

接著**明確詢問要建置哪些旅宿**，可用 AskUserQuestion 讓使用者複選。

- **只處理使用者同意的旅宿**；未獲同意的一律不動
- 使用者要求新增清單以外的旅宿時，照辦
- 沒有得到回覆前，**不進入步驟 5**，也不抓取任何網頁

### 5. 查證

每間要寫的旅宿，依序：

1. **訂房文件優先**：確認碼、PIN、日期、房型、人數、房價、取消政策、清潔費一律照抄訂房 PDF
2. **官方網站次之**：設施時間、館內規定、入住流程；連鎖品牌看分館頁不看總站頁
3. 周邊生活機能用地圖與在地資訊網站補充，並在指南中註明資料日期
4. 抓取失敗（403／逾時）時不臆測內容，在指南中標為「未確認」，並於回報中列為「無法取得」

**必查項目**（缺一項就要在指南中註明未確認）：

- Check-in／check-out 時間，以及**櫃台是否有人**、無人櫃台的入住流程
- 早餐供應時間與型式，是否含在房價內
- 大浴場、溫泉、洗衣設備的**開放時段**（含清掃停用時段）
- 行李寄放：入住前與退房後各能不能放、到幾點、是否收費
- 取消政策的**免費取消截止日**與逾期罰則金額
- 訂房時看不到的額外支出：清潔費、城市稅、停車費
- 周邊便利商店、超市、購物中心、藥妝、可用餐廳的位置與營業時間
- 特殊限制：刺青、門禁、垃圾處理、禁止聚會、禁菸

### 6. 撰寫檔案

依 `hotel_format.md` 的範本撰寫，並確保：

- 「本次行程使用規劃」章節對應到實際日期與 `days/yyyyMMDD.md` 的入住、早餐、出發、退房時間
- 與 `days/` 現有內容衝突時（步行時間、退房時間、早餐供應），在指南中以 `> ⚠️` 標明差異並指出以訂房文件或官方現行公告為準
- 現場容易踩到的坑用 `> ⚠️` 獨立標示
- 檔案開頭加 `> 🔒` 敏感資訊提醒

### 7. 撰寫聯絡確認信件

在該旅宿檔案的 `## 聯絡確認信件` 章節，寫四個情境、**英文與日文各一封**：

1. **行前住宿內容確認**——訂房是否成立、日期、房型、人數、餐飲、預計抵達時間
2. **入住手續與鑰匙領取**——無人櫃台流程、大門與智慧鎖密碼、鑰匙歸還方式
3. **抵達時間變更／晚到通知**——實際抵達時間與訂房時填的不同
4. **行李寄放與其他需求**——入住前或退房後寄放、提早入住、加床、禁菸房、樓層

規則：

- 信中的訂房編號、日期、人數、房型**一律取自本檔「基本資訊」表**，**不得杜撰**
- 沒查到的資訊就不要寫進信裡，改成向館方提問
- 一封信只問一件事；英文日期用 `31 August 2026` 這類無歧義格式
- 信末附訂房人姓名與確認碼

### 8. 整理飯店回信

使用者把館方回信貼進來、或既有指南已有回信時，整理進該旅宿檔案的 `## 飯店回信` 章節（放在 `## 聯絡確認信件` 之後、`## 官方資訊來源` 之前）：

1. 一封回信一個 `### {YYYY.MM.DD}` 小節，日期寫**收信日**，多封由舊到新排列
2. 內文**原文照抄**放進 fenced code block，日文與英文都寄來就兩段一起收，不翻譯、不改寫、不刪節，館方原本的分隔線與符號保留
3. 讀出回信裡的可執行資訊——入住與行李寄放時間、事前登記（本人確認）要求、密碼或入室碼的發送時間、加購與付款方式
4. 把這些資訊同步寫回「基本資訊」「入住與退房方式」「特殊規定」「本次行程使用規劃」，回信本身只當存證，不當唯一出處
5. 回信與既有欄位（官網公告、訂房 PDF 以外的資料）不一致時**以回信為準**，在對應欄位用 `> ⚠️` 標明差異與回信日期
6. 回信要求使用者採取行動時（例如前一天前完成線上登記、回覆抵達時間），在回報中列出並提醒

規則：

- **不代館方潤稿**，也不把回信內容改寫成中文摘要放進 code block
- 回信與**訂房 PDF** 的訂房事實（確認碼、日期、房型、人數、房價、取消政策）衝突時，**先詢問使用者**，不自行改寫基本資訊表
- 回信含個人資料或訂房識別碼時，沿用檔頭的 `> 🔒` 提醒即可，不另外遮蔽

### 9. 連結回每日行程與 README

在對應 `days/yyyyMMDD.md` 標頭的「住宿」列之後加入連結：

```markdown
- **旅宿指南**：[{名稱}](../hotel/{檔名}.md)（{當天實際會用到的部分}）
```

並在 `README.md` 的「旅宿資訊」表加入或更新該旅宿的一列。

**修改 `days/` 前，先依 `update-itinerary` 技能的歸檔步驟**，將受影響檔案複製到 `archive/{YYYYMMDD-HHMM}/days/`。

### 10. 回報

完成後條列：

- 新建的指南（檔名、涵蓋旅宿、期間）
- 補充的既有指南（補了哪些欄位）
- 產出的信件情境數量與語言
- 加了連結的 `days/` 檔案與歸檔目錄
- 收錄的飯店回信（旅宿、收信日）與回信帶出的行程影響、需要使用者回覆或事前登記的事項
- **與現有行程不一致之處**（步行時間、退房時間、早餐供應、費用），並詢問是否更正
- 無法取得資料的來源與原因

最後提醒使用者：本次若抓取過新網站，需執行 `/save-website-abstract`（旅館官網歸「住宿」分類）。

## 限制

- **未經使用者同意不建立任何檔案**：步驟 4 的清單確認是硬性關卡，不因旅宿「明顯需要」而略過
- **不代為寄出任何信件**，只產出可複製的文字；不呼叫任何寄信工具
- **信件不得杜撰訂房編號、房價、日期、人數**，一律取自訂房文件
- **飯店回信原文照抄**，不翻譯、不改寫、不刪節；回信與訂房 PDF 的訂房事實衝突時先詢問使用者
- 不修改 `assets/` 內的訂房 PDF，也不修改 `assets/reference_website.md`（由使用者維護）
- 不修改 `reference/` 內的格式規範檔
- 不擅自更動 `days/` 的行程內容；標頭連結以外的修正先詢問使用者
- 不代填、不代改每日檔頂部的審閱橫幅
- 所有說明文字使用繁體中文；旅館與店名保留日文原名；**信件本體為英文與日文**
